# Software DOI and Archival Plan

## Goal

Mint a **verified DOI** for a versioned release of the U.S. Small Business Capital Access
Atlas through Zenodo's official GitHub integration.

## Current status

The repository is DOI-ready:

- public GitHub repository;
- MIT license;
- `CITATION.cff`;
- CodeMeta metadata;
- versioned GitHub releases;
- reproducible tests and validation;
- PyPI Trusted Publishing; and
- release notes / changelog.

A DOI is **not claimed until Zenodo actually mints one**.

## Required account authorization

Zenodo requires the repository owner to authorize Zenodo's GitHub integration and enable
this specific repository. That OAuth/account step cannot be performed by repository code.

Official instructions:
https://help.zenodo.org/docs/github/enable-repository/

Enable:

`sakera023/us-small-business-capital-access-atlas`

After the repository is enabled, the **next GitHub release** will be ingested by Zenodo and
assigned a DOI.

Official release-archiving instructions:
https://help.zenodo.org/docs/github/archive-software/github-upload/

## Planned DOI release

The next archival release should be **v0.3.0**, containing:

- county-level Census CBP analysis;
- Census TIGERweb county mapping;
- corrected Certified CDFI institution-level integration;
- expanded robustness benchmarks;
- PyPI release automation; and
- external-replication/adoption infrastructure.

Before creating v0.3.0:

1. enable the repository in Zenodo;
2. update `pyproject.toml`, `CITATION.cff`, and CodeMeta to 0.3.0;
3. move the Unreleased changelog entries into 0.3.0;
4. pass CI and public-data validation;
5. publish GitHub release v0.3.0;
6. confirm Zenodo created the software record and DOI;
7. publish/verify the matching PyPI 0.3.0 release; and
8. add the verified DOI to README, citation metadata, and project URLs.

## DOI integrity rule

Do not:

- invent a DOI;
- use a placeholder DOI in citation metadata;
- claim Zenodo archival before the record exists; or
- claim a DOI generated by an unrelated record.

The repository should display only a DOI that resolves to the archived Atlas software
record.
